# StoryTime

A brand-new bedtime story for your child every night, written and narrated entirely on the phone.

StoryTime is a standalone iOS app built with .NET MAUI. There is no server, no account and no network use, and no model files are bundled or downloaded. Text is generated by Apple's on-device Foundation Models (iOS 26+). Narration uses Apple speech synthesis, shaped by StoryTime's own prosody and "cozy mastering" chain. Each story gets a procedurally composed parallax poster and, with Premium, an ambient music bed. Parental oversight is built into the structure: teaser approval, Face ID-locked parent settings, a browse-only Kid Shelf and a cooldown between stories.

Text comes from Apple's on-device Foundation Models through `AppleFoundationStoryEngine` (registered in `RegisterStoryEngine`, `src/app/StoryTime.App/MauiProgram.cs`); when the model is off, downloading or unavailable, the deterministic `TemplateStoryEngine` writes the story instead, and Home shows a short notice when the parent can turn Apple Intelligence on. Narration still uses MAUI platform TTS; its swap point is `RegisterTtsEngine`.

## Layout

| Path | What |
|---|---|
| `src/app/StoryTime.App` | MAUI iOS head (`net10.0-ios`, iOS 26.0+): views, platform services, DI |
| `src/app/StoryTime.Core` | Platform-free core: pipeline, engines, prompts, narration DSP, persistence, view-models |
| `src/shared/StoryTime.Contracts` | Shared DTOs |
| `src/native/StoryTimeNative` | Swift native-features framework, one folder per feature (`FoundationModels/` today). XcodeGen spec; iOS 27.0 target |
| `src/native/StoryTimeNative.Binding` | .NET for iOS binding of that framework (`ApiDefinition.cs`) |
| `src/native/lab` | macOS lab: runs the real C# engine against the same Swift shim on the Mac |
| `tests/StoryTime.Core.Tests` | xUnit tests for Core |
| `docs/` | PRD, architecture, and the binding UI contract `docs/design/mockup-spec.md` |

## Build, test, run

You need the user-local .NET 10 SDK under `~/.dotnet` with the `maui` and `ios` workloads, plus Xcode. Source the environment first. The system `dotnet` cannot build this repo.

```sh
source src/build-env.sh

dotnet build src/app/StoryTime.Core/StoryTime.Core.csproj
dotnet test  tests/StoryTime.Core.Tests/StoryTime.Core.Tests.csproj

# iOS simulator
dotnet build src/app/StoryTime.App/StoryTime.App.csproj -f net10.0-ios -p:RuntimeIdentifier=iossimulator-arm64
xcrun simctl boot "iPhone 17"
xcrun simctl install booted src/app/StoryTime.App/bin/Debug/net10.0-ios/iossimulator-arm64/StoryTime.App.app
xcrun simctl launch booted net.frostaura.storytime

# device compile (needs a provisioning profile for net.frostaura.storytime)
dotnet build src/app/StoryTime.App/StoryTime.App.csproj -f net10.0-ios -p:RuntimeIdentifier=ios-arm64
```

Every project builds with warnings treated as errors. Zero warnings is a build gate.

## Native framework (Foundation Models)

Text generation runs through `StoryTimeNative`, a small Swift framework whose `SEFMEngine` is an `@objc`, completion-handler, JSON-in/JSON-out shim over Apple's Foundation Models. The C# side (`Core/Engines/AppleFoundation`) owns prompts, budgets and the failure ladder; the shim only runs sessions.

- `src/native/build.sh` builds `src/native/build/StoryTimeNative.xcframework` (device + simulator) with Xcode 27 and XcodeGen. The output is gitignored and is **not** committed: the binding project runs the script automatically when the xcframework is missing, so `dotnet build` of the app works from a clean clone. Rebuild by hand after changing Swift sources (`src/native/build.sh`).
- After changing `Info.plist`, run a full rebuild (`-t:Rebuild`): the incremental iOS build has been seen to keep the previous bundle `Info.plist`.
- `src/native/lab/run-fm-lab.sh [sceneCount]` (macOS 27 with Apple Intelligence on) compiles the shim for macOS and runs the real `AppleFoundationStoryEngine` end to end through a pipe bridge; the story and timings land in `.tmp/fm-lab/`. Results: `docs/research/genai-lab-fm-shim.md`.
