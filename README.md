# StoryTime

A brand-new bedtime story for your child every night, written and narrated entirely on the phone.

StoryTime is a standalone iOS app built with .NET MAUI. There is no server and no account, the only network use is the App Store for the optional one-off Premium purchase, and no model files are bundled or downloaded. Text is generated by Apple's on-device Foundation Models (iOS 26+). Narration uses Apple speech synthesis, shaped by StoryTime's own prosody and "cozy mastering" chain. Each story gets a procedurally composed parallax poster and, with Premium, an ambient music bed. Parental oversight is built into the structure: teaser approval, Face ID-locked parent settings, a browse-only Kid Shelf and a cooldown between stories.

Current baseline: the app runs end to end on the deterministic `TemplateStoryEngine` and MAUI platform TTS. The Apple engines plug into two named swap points in `src/app/StoryTime.App/MauiProgram.cs`, `RegisterStoryEngine` and `RegisterTtsEngine`.

## Layout

| Path | What |
|---|---|
| `src/app/StoryTime.App` | MAUI iOS head (`net10.0-ios`, iOS 26.0+): views, platform services, DI |
| `src/app/StoryTime.Core` | Platform-free core: pipeline, engines, prompts, narration DSP, persistence, view-models |
| `src/shared/StoryTime.Contracts` | Shared DTOs |
| `tests/StoryTime.Core.Tests` | xUnit tests for Core |
| `docs/` | PRD, architecture, and the binding UI contract `docs/design/mockup-spec.md` |

## Build, test, run

You need the user-local .NET 10 SDK under `~/.dotnet` with the `maui` and `ios` workloads, plus Xcode. Source the environment first. The system `dotnet` cannot build this repo.

```sh
source src/build-env.sh

dotnet build src/app/StoryTime.Core/StoryTime.Core.csproj
dotnet test  tests/StoryTime.Core.Tests/StoryTime.Core.Tests.csproj

# iOS simulator
dotnet build src/app/StoryTime.App/StoryTime.App.csproj -f net10.0-ios -p:RuntimeIdentifier=iossimulator-arm64
xcrun simctl boot "iPhone 17"
xcrun simctl install booted src/app/StoryTime.App/bin/Debug/net10.0-ios/iossimulator-arm64/StoryTime.App.app
xcrun simctl launch booted net.frostaura.storytime

# device compile (needs a provisioning profile for net.frostaura.storytime)
dotnet build src/app/StoryTime.App/StoryTime.App.csproj -f net10.0-ios -p:RuntimeIdentifier=ios-arm64
```

Every project builds with warnings treated as errors. Zero warnings is a build gate.

## Premium (App Store, on device)

Premium is one non-consumable in-app purchase, `net.frostaura.storytime.premium`: paid once, no subscription, no account, no server. StoreKit runs on the phone (`Platforms/iOS/StoreKitPremiumStore.cs`); the purchase is recorded locally and re-checked with **Restore purchase**. It unlocks 15-minute stories, music under narration and a 15-minute (instead of 30-minute) wait between stories.

- **Founder action:** create the product in App Store Connect (type *Non-Consumable*, product ID `net.frostaura.storytime.premium`, reference name "StoryTime Premium", a price tier and an en-US localization), then submit it with the first build. Until it exists the Premium page says Premium can't be bought from the App Store right now; everything free keeps working.
- **Local testing:** `src/app/StoryTime.App/Platforms/iOS/StoryTime.storekit` is a StoreKit configuration with the same product. To use it, open the built app in an Xcode scheme, set *Run → Options → StoreKit Configuration* to that file, and run on a simulator; purchases, Ask to Buy, failures and refunds can then be driven from Xcode's transaction manager. A plain `simctl launch` has no StoreKit configuration and no sandbox account, so the page shows the store-unavailable or not-found state.
- StoreKit 1 is used because it is the StoreKit surface bound for .NET for iOS. Apple marks it obsoleted from iOS 18 (it still works on iOS 26), so `StoreKitPremiumStore.cs` alone suppresses CA1422. Moving to StoreKit 2 needs a Swift bridge.
