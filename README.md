# StoryTime

A brand-new bedtime story for your child every night, written and narrated entirely on the phone.

StoryTime is a standalone iOS app built with .NET MAUI. There is no server and no account, the only network use is the App Store for the optional one-off Premium purchase, and no model files are bundled or downloaded. Text is generated by Apple's on-device Foundation Models. The minimum OS is iOS 27 (founder decision): the app head, the binding and the native shim all target iOS 27.0, built on the Microsoft.iOS 27.0 pack with Xcode 27. Narration uses Apple speech synthesis, shaped by StoryTime's own prosody and "cozy mastering" chain. Each story gets a procedurally composed parallax poster and, with Premium, an ambient music bed. Parental oversight is built into the structure: teaser approval, Face ID-locked parent settings, a browse-only Kid Shelf and a cooldown between stories.

Text comes from Apple's on-device Foundation Models through `AppleFoundationStoryEngine` (registered in `RegisterStoryEngine`, `src/app/StoryTime.App/MauiProgram.cs`); when the model is off, downloading or unavailable, the deterministic `TemplateStoryEngine` writes the story instead, and Home shows a short notice when the parent can turn Apple Intelligence on. Narration still uses MAUI platform TTS; its swap point is `RegisterTtsEngine`.

## Build, test, run

The repository is [`frostaura/labs.fa.story-time`](https://github.com/frostaura/labs.fa.story-time) (formerly `fa.story-time`); the app lives on branch `feat/maui-standalone`. Clone it outside iCloud Drive:

```sh
gh repo clone frostaura/labs.fa.story-time ~/src/labs.fa.story-time
cd ~/src/labs.fa.story-time && git checkout feat/maui-standalone
```

You need the user-local .NET 10 SDK under `~/.dotnet` with the `maui` and `ios` workloads, plus Xcode. Source the environment first. The system `dotnet` cannot build this repo.

```sh
source src/build-env.sh

dotnet build src/app/StoryTime.Core/StoryTime.Core.csproj
dotnet test  tests/StoryTime.Core.Tests/StoryTime.Core.Tests.csproj

# iOS simulator
dotnet build src/app/StoryTime.App/StoryTime.App.csproj -f net10.0-ios -p:RuntimeIdentifier=iossimulator-arm64
xcrun simctl boot "iPhone 17"
xcrun simctl install booted src/app/StoryTime.App/bin/Debug/net10.0-ios/iossimulator-arm64/StoryTime.App.app
xcrun simctl launch booted net.frostaura.storytime

# device compile (needs a provisioning profile for net.frostaura.storytime)
dotnet build src/app/StoryTime.App/StoryTime.App.csproj -f net10.0-ios -p:RuntimeIdentifier=ios-arm64
```

Every project builds with warnings treated as errors. Zero warnings is a build gate.

## Premium (App Store, on device)

Premium is one non-consumable in-app purchase, `net.frostaura.storytime.premium`: paid once, no subscription, no account, no server. StoreKit 2 runs on the phone through the native shim (`src/native/StoryTimeNative/Sources/Store/SESKStore.swift`), bound behind Core's `IPremiumStore` (`Core/Services/StoreKitPremiumStore.cs` over `Platforms/iOS/AppStoreBridge.cs`); every transaction is JWS-verified, the purchase is recorded locally, and **Restore purchase** runs `AppStore.sync()`. A `Transaction.updates` listener starts at launch, so Ask to Buy approvals, purchases on another device, refunds and revocations land without the Premium page open. It unlocks 15-minute stories, music under narration and a 15-minute (instead of 30-minute) wait between stories.

- **Founder action:** create the product in App Store Connect (type *Non-Consumable*, product ID `net.frostaura.storytime.premium`, reference name "StoryTime Premium", a price tier and an en-US localization), then submit it with the first build. Until it exists the Premium page says Premium can't be bought from the App Store right now; everything free keeps working.
- **Local testing:** `src/app/StoryTime.App/Platforms/iOS/StoryTime.storekit` is a StoreKit configuration with the same product. To use it, open the built app in an Xcode scheme, set *Run → Options → StoreKit Configuration* to that file, and run on a simulator; purchases, Ask to Buy, failures and refunds can then be driven from Xcode's transaction manager. A plain `simctl launch` has no StoreKit configuration and no sandbox account, so the page shows the store-unavailable or not-found state.

## Native framework (Foundation Models and StoreKit 2)

`StoryTimeNative` is a small Swift framework of `@objc`, completion-handler shims for the Apple APIs .NET for iOS does not bind:

- `SEFMEngine` (`Sources/FoundationModels`): JSON-in/JSON-out over Apple's Foundation Models, including the guided poster choice (poster spec contract v3). The C# side (`Core/Engines/AppleFoundation`) owns prompts, budgets and the failure ladder; the shim only runs sessions.
- `SESKStore` (`Sources/Store`): StoreKit 2 — `Product.products(for:)`, `purchase(confirmIn:)`, `Transaction.updates`, `Transaction.currentEntitlements` / `latest(for:)` and `AppStore.sync()`. Outcomes are `PremiumPurchaseResult` names; the C# side owns the local ledger.

- `src/native/build.sh` builds `src/native/build/StoryTimeNative.xcframework` (device + simulator) with Xcode 27 and XcodeGen. The output is gitignored and is **not** committed: the binding project runs the script automatically when the xcframework is missing, so `dotnet build` of the app works from a clean clone. Rebuild by hand after changing Swift sources (`src/native/build.sh`).
- After changing `Info.plist`, run a full rebuild (`-t:Rebuild`): the incremental iOS build has been seen to keep the previous bundle `Info.plist`.
- `src/native/lab/run-fm-lab.sh [sceneCount]` (macOS 27 with Apple Intelligence on) compiles the shim for macOS and runs the real `AppleFoundationStoryEngine` end to end through a pipe bridge; the story and timings land in `.tmp/fm-lab/`. Results: `docs/research/genai-lab-fm-shim.md`.
